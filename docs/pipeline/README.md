## 当前语义快照

- SSA merge 已使用 block parameters：branch/goto/switch target arguments 负责传递 predecessor frame value，LLVM backend lower 成 `phi`。local frame 只合并 successor live-in slot，dead slot 可跨分支缺失或复用不同类型；需要 throw-site handler locals 的合法复杂 exception flow 当前走 encoded JVM fallback。
- Exception base 已支持 typed catch handler exception parameter、IR exceptional edge metadata、`THROW` terminator、implicit null/array/cast/div-zero exception site metadata，以及简单 catch-all rethrow / normal+exceptional cleanup shape。multi-exit finally、exception state merge、monitor/finally interaction 等仍精确 `frontendSkipped`。
- Monitor/JMM base 已支持 `monitorenter` / `monitorexit`、`ACC_SYNCHRONIZED` method、识别出的 synchronized exceptional cleanup helper-backed lowering、volatile read/write fence、final field publication fence、monitor happens-before marker、Thread.start/join happens-before helper。`Thread.<init>(Runnable)` / `start` / `join` 和 `Object.wait/notify` 当前保持 JVM helper fallback boundary，不做 native scheduler 或 monitor queue。
- Class initialization skeleton 已支持 active-use guard：跨 owner `getstatic` / `putstatic` / `invokestatic` 和 `new` 插入 class object + guard；同 owner static field / static invoke 不递归 guard，因为当前 owner 已处于初始化语义内。`<clinit>` body 插入 begin/end/failed helper，同 owner `<clinit>` self access 不递归 guard。
- Runtime ABI 已有 catalog/signature/category model，可生成稳定 `runtime-helpers.h` 和 C skeleton；helper reference ABI token 使用 JNI handle 类型（`jobject` / `jclass` / `jarray` / `jthrowable`），C prototype 显式接收 `JNIEnv* env`，LLVM helper declaration 由同一 catalog 映射到 opaque `ptr`。
- JDK bootstrap 已有 `JdkIntrinsicRegistry` policy：Object/String/StringBuilder/System.arraycopy/Math/boxing/Objects 第一批走 direct/runtime helper；当前 host E2E 覆盖 String `isEmpty` / `charAt` / `startsWith` / `endsWith` / `substring(int,int)`、显式 StringBuilder append chain、System.arraycopy byte/int/long/double/object/overlap/null/oob/ArrayStoreException、Integer/Long/Boolean/Double boxing-unboxing、Objects.requireNonNull/equals 和 Math int/long/float/double abs/min/max。ArrayList `add/get/size/contains`、HashMap `put/get/containsKey/overwrite`、`Arrays.copyOf/equals/fill/asList`、`Collections.emptyList/singletonList`、`Optional.of/ofNullable/isPresent/get/orElse`、`String.format(String,Object...)`、Throwable message/cause common paths 和 Thread start/join common paths 当前使用明确 JVM fallback policy，经 encoded fallback 保持 JVM collection/Optional/formatter/array-library/Throwable/Thread 语义；未知 JDK call 走 `halfLowered` JVM helper fallback warning。
- Runtime metadata 已有稳定 index/dump，覆盖 Signature、runtime annotations、record、nest/inner、bridge/synthetic/record generated flags 和 class init/class object handle。Static reflection 可解析 class literal、常量 Class.forName、常量 getDeclaredMethod/Field/Constructor，并把反射 target 接入 call graph reachability；no-arg、reference、primitive 和 array 常量参数 descriptor 的 method/constructor invoke 已进入 helper path。动态 `Class.forName`、动态 member name/parameter array 和 scan-style reflection 普通调用在 descriptor 可通过 JNI bridge 表达时走 JVM dispatch bridge；超出 bridge descriptor 或无法安全保留 owner bytecode context 的形态才 fallback/skip，并必须有 reason。
- JNI 第一层已有 descriptor -> JNI C type、reference/local-frame/pending-exception policy、RegisterNatives table、JNI_OnLoad/bootstrap wrapper plan 和 symbol allowlist。当前 JVM-hosted vertical slice 已能生成 JNI C skeleton、managed Zig `build.zig` workspace、当前 host 动态库、唯一 Java 17 `<embeddedLibraryDirectory>/Loader.class`、SHA-256 校验、`System.load` 和 `JNI_OnLoad` / `RegisterNatives` runtime binding，覆盖 `LLVM_NATIVE_PATH` 的 static/instance primitive scalar add/long/double/boolean compare/void no-op、if/else、nested if、block-parameter/phi merge、table/lookup switch、JVM numeric helper opcodes、static/instance/volatile field helper path、monitor/synchronized helper path、explicit `athrow` -> JNI `Throw` bridge、static reflection method/constructor/field helper path（含常量参数 method/constructor invoke）、Unsafe `objectFieldOffset` token / `getInt` / `putInt` / monitor-backed `compareAndSwapInt` / `allocateInstance` helper path、typed-int VarHandle helper path、div/rem ArithmeticException helper、String/reference field pass-through、broad primitive/reference array helper subset、System.arraycopy byte/int/long/double/object/overlap/null/oob/ArrayStoreException helper、selected primitive/reference array allocation helpers、ordinary-method object construction helper subset、`checkcast` / `instanceof` helper subset、String `length` / `equals` helpers、StringConcatFactory `makeConcat` / common `makeConcatWithConstants` helper path、LambdaMetafactory common `metafactory` helper path、LDC MethodHandle + `invokeExact` direct path、Math `abs/min/max` int/long helper subset、same-class selected static/private-special direct call，以及 tokenized virtual/interface JVM dispatch helper 的 no-arg int、int-arg int 和 reference-return subset。dispatch helper 使用 JNI `Call<Type>Method`，不实现 native vtable。`TEMPLATE_JNI_PATH` / helper path 仍覆盖 String content JNI path、`int[]` copy/new-array API、`ThrowNew` exception bridge smoke path、generic straight-line/simple-branch constructor/class-initializer body helper first layer 和更广泛 helper/fallback 边界。
- Native build 的正式路径是 managed Zig `0.15.2` 统一接管 `.ll`、Zig-managed `.o`、JNI wrapper C、runtime helper C 和 fallback blob carrier sources。Zig 安装目录固定为可执行 `j2ll.jar` 同级的 `zig/zig(.exe)`；缺失时先使用同目录已有官方 Zig archive，仍缺失再从 Zig 官方 download path 下载；local/downloaded archive 必须按内置官方 SHA-256 metadata 校验，通过后才将官方 archive 根目录内容规范化到 `zig/`，checksum mismatch 是 toolchain failure。Signature verification 当前明确报告 `notVerifiedBoundary`。Java 侧只生成一个 `build.zig` workspace 并执行 managed `zig build`；不要新增 host `cc` / `clang` / `zig cc` ad-hoc path。Packaging report 的 `zigToolchain.bootstrapEvents` 记录 found/reinstall/local-archive/download/checksum/install 等用户可诊断事件，并包含 archiveName/archiveSha256/checksumStatus/signatureStatus/source。
- Cross-target native build 当前固定支持 `x86_64-windows-gnu`、`aarch64-windows-gnu`、`x86_64-linux.3.2-gnu.2.17`、`aarch64-linux.3.7-gnu.2.17`、`x86_64-macos.10.15` 和 `aarch64-macos.11.0`。它们由一个 `build.zig` 和一次 matrix-wide invocation 生成真实 DLL/SO/dylib；portable JNI target headers 避免混入 host `jni_md.h`，PE/ELF/Mach-O inspector 校验 format、architecture 和 export allowlist。跨平台结构性产物证据与 target OS/JVM runtime E2E 分开记录。
- Runtime Loader 契约固定为唯一 `<embeddedLibraryDirectory>/Loader.class`：native loading 始终存在，仅在 implementation plan 实际使用 `nativeEmbeddedClassBlob` 时保留 `defineHiddenFallback`；旧 `J2llFallbackSupport.class`、`J2llNativeLoaderSupport.class` 和 `j2ll/generated/**/NativeLoader.class` 不再输出。目录必须是规范 Java internal package path。输入 base/MR 同名 Loader 分别以 `GENERATED_RUNTIME_LOADER_ENTRY_COLLISION` / `GENERATED_RUNTIME_LOADER_VERSIONED_SHADOW` 在 Zig 前失败。同一 defining `ClassLoader` 中多个不同产物复用同一目录仍是已知边界，建议使用应用唯一目录。
- invokedynamic base 已支持 StringConcatFactory `makeConcat` 到真实 StringBuilder helper E2E；`makeConcatWithConstants` 常见 recipe 已通过 tokenized native constant carrier + StringBuilder helper E2E。LambdaMetafactory `metafactory` common path 已通过 JVM `LambdaMetafactory` helper E2E；MethodHandle `bindTo` / `asType` / `dropArguments` / `permuteArguments` / `filterArguments` / `foldArguments` / collector-style common adapter chain 已通过 JVM `MethodHandle.invokeWithArguments` bridge E2E。该 path 不是 generic native MethodHandle interpreter；完整 altMetafactory runtime class semantics、unsupported ConstantDynamic 和更复杂 MethodHandle/lambda shape 仍按 skeleton/fallback 边界处理。
- Unsafe/VarHandle bounded subset 已 helper-backed lowering，并对 volatile/CAS 发 JMM marker；当前真实 E2E 覆盖 statically resolved field-token `Unsafe` int access/CAS、`allocateInstance` 和 typed-int VarHandle get/set/volatile/CAS，offset/token 不表示 native object address；unsupported memory access API 走明确 fallback 诊断。
- catch-all/finally 已支持简单 rethrow 和 normal/exceptional cleanup shape；multi-exit/state-merge/monitor-finally interaction 仍精确 `frontendSkipped`。
- Runtime metadata/static reflection/JNI ABI/Unsafe/helper facts 已进入主线 reports：runtime metadata dump 写入 `intermediates/runtime/runtime-metadata.json`，lowering report 的 `helperBackedSites` 标注 `RUNTIME_METADATA_HELPER`、`REFLECTION_HELPER`、`REFLECTION_FIELD_HELPER`、`REFLECTION_METHOD_HELPER`、`REFLECTION_CONSTRUCTOR_HELPER`、`REFLECTION_ACCESSIBLE_HELPER`、`UNSAFE_HELPER`、`VARHANDLE_HELPER`、`JNI_ABI_REGISTER_NATIVES`、`FIELD_HELPER`、`ARRAY_HELPER`、`ARRAYCOPY_HELPER`、`ALLOCATION_HELPER`、`TYPE_HELPER`、`STRING_HELPER`、`STRING_BUILDER_HELPER`、`STRING_CONCAT_CONSTANTS_HELPER`、`LAMBDA_METAFACTORY_HELPER`、`JDK_INTRINSIC_HELPER`、`JDK_COLLECTION_HELPER`、`THROWABLE_HELPER`、`THREAD_HELPER`、`WAIT_NOTIFY_FALLBACK`、`JMM_FENCE`、`MONITOR_HELPER`、`SYNCHRONIZED_METHOD_HELPER`、`EXCEPTION_HELPER`、`DIV_REM_EXCEPTION_HELPER`、`DIRECT_LLVM_CALL`、`JVM_CALL_HELPER`、`DISPATCH_HELPER`、`DEFAULT_INTERFACE_DISPATCH_HELPER`、`DEFAULT_INTERFACE_DISPATCH_FALLBACK`、`UNSUPPORTED_DEFAULT_INTERFACE_CONFLICT`、`UNSUPPORTED_DEFAULT_INTERFACE_SUPER`、`DEFERRED_DISPATCH_HELPER`、`CONSTRUCTOR_CALL_HELPER`、`CONSTRUCTOR_BODY_HELPER` 和 `CLASS_INITIALIZER_BODY_HELPER`。Packaging report 的 fallback blob 记录 `fallbackInvokeDescriptor`、`fallbackReasonCode`、`FALLBACK_HIDDEN_CLASS` / `FALLBACK_DEFINE_CLASS` / `FALLBACK_HIDDEN_CLASS_UNAVAILABLE` / `FALLBACK_HIDDEN_CLASS_UNSUPPORTED_ACCESS` definition capability reason code、`FALLBACK_CACHE_REUSE` cache reason，以及 `cacheScope` / `cacheKey` / `cacheLifetime` / `globalReferencePolicy` / `unloadAware=false` / `futurePath` lifecycle 字段；target preflight 通过 diagnostics/report 记录 `ZIG_TARGET_PREFLIGHT` 或 required-target failure `ZIG_TARGET_UNBUILDABLE`，并带 required、Zig triple、failure kind、SDK requirement 和 build log tail；packaging report 还记录 JAR preservation summary 和 signature action。
- `nativeEmbeddedClassBlob` fallback 目前有稳定 planner/report 和真实 ordinary-method bytecode body path：helper class bytes 不作为 JAR 明文 `.class` entry 输出，而是以 v1 `j2ll-rle-byte-pairs-v1` + `xor-sha256-key-stream-v1` encoded blob 编入 host native artifact。对于可 JNI 桥接的 ordinary `halfLowered` 方法，packaging 会把原 method body 复制为同 owner package hidden/helper class 的 static synthetic `invoke` 方法；instance fallback 把 `this` 作为第一个参数传入，static fallback 使用 owner `jclass`，primitive/reference 参数和返回通过 JNI `CallStatic<Type>Method` 桥接，fallback body 抛出的 pending exception 直接传播。JNI 在 native-side SHA-256 校验后解码，再通过唯一 Loader 中按需保留的 `defineHiddenFallback` 获取 owner-private `MethodHandles.Lookup` 并优先 `defineHiddenClass` lazy define/reuse。JDK 或 owner-private Lookup 不满足时选择已实现的 JNI `DefineClass` 兼容机制并记录 `FALLBACK_HIDDEN_CLASS_UNAVAILABLE` / `FALLBACK_HIDDEN_CLASS_UNSUPPORTED_ACCESS`。decoder 对 encoded hash、wrong key/fallback id 和 corrupted RLE payload 有 bounded validation，避免 malformed blob 触发 unbounded allocation。runtime cache 是 fallback id + classloader identity 的 process-lifetime linked global-ref cache；report 明确 `unloadAware=false`，不承诺 classloader unload 释放 native global-ref cache；child JVM E2E 已覆盖同一 output JAR 经两个独立 `URLClassLoader` 加载时的隔离注册和 fallback 调用。

## 维护规则

- 新增 stage、fallback 策略、validator、测试落点或目录边界时，先更新 `AGENTS.md`，再更新对应 stage guide。
- README 保持用户视角；内部 rewrite 计划和 compiler 设计只放在 `docs/`。
- 单个 stage guide 应保持 focused。跨阶段规则放在本索引、`00-overview.md` 或 `08-diagnostics-validation-testing.md`。
